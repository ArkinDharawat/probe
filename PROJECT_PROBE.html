Probe

Personal Research MCP Server — ingest papers, filings, Substack, tweets → extract → analyze via RAG → expose to Claude Code over stdio

Architecture

Probe is an MCP server first. Claude Code is the only client. Claude parses PDFs and HTML natively and hands the server already-extracted markdown plus provenance. The server doesn't fetch URLs or parse binary formats.

Claude Code (MCP client)
│ stdio
probe serve (MCP server)
probe serve (MCP server)
  │
  ├─ ingest(content, provenance, source_type)   → Chunks + Provenance → SQLite
  ├─ search_personal_knowledge(query, limit)    → sqlite-vec + FTS5 + RRF
  ├─ get_document(doc_id)                       → full doc + extractions + analyses
  ├─ extract(doc_id)                            → Anthropic API → structured output
  ├─ analyze(doc_id)                            → RAG context + Anthropic API → connections
  ├─ evaluate_thesis(claim_or_id)               → RAG → support/contradict verdict
  ├─ list_theses(status)                        → tracked theses
  └─ add_note(content, tags)                    → ergonomic ingest wrapper

The CLI collapses to a launcher: probe serve (start the MCP server) and optional probe stats (out-of-band DB debugging from the terminal). Everything else is an MCP tool.

Data Model

-- Every ingested source
documents (
    id TEXT PRIMARY KEY,          -- uuid
    source_type TEXT NOT NULL,    -- 'arxiv', 'substack', 'tweet', 'filing', 'pdf', 'markdown'
    source_url TEXT,              -- original URL (nullable for pasted text)
    title TEXT,
    author TEXT,
    published_at TEXT,            -- ISO date if known
    accessed_at TEXT NOT NULL,    -- when you ingested it
    description TEXT,             -- user-provided context if no URL
    raw_path TEXT,                -- path to cached original in ~/.probe/raw/
    metadata JSON                 -- source-specific extras
)

-- Chunks with embeddings
chunks (
    id TEXT PRIMARY KEY,
    document_id TEXT REFERENCES documents(id),
    content TEXT NOT NULL,
    section TEXT,                 -- 'abstract', 'risk_factors', 'paragraph_3', etc.
    chunk_index INTEGER,
    metadata JSON,                -- per-chunk extras (e.g. page_number for PDFs)
    embedding BLOB                -- 384d float32 via sqlite-vec
)

-- FTS5 virtual table for keyword search
chunks_fts (content)             -- mirrors chunks.content

-- Structured extractions (domain-specific output)
extractions (
    id TEXT PRIMARY KEY,
    document_id TEXT REFERENCES documents(id),
    extraction_type TEXT NOT NULL, -- 'paper', 'financial', 'general'
    output JSON NOT NULL,          -- domain-specific structured data
    prompt_version TEXT,
    created_at TEXT
)

-- Analysis results (RAG connections)
analyses (
    id TEXT PRIMARY KEY,
    document_id TEXT REFERENCES documents(id),
    connections JSON NOT NULL,
    new_information JSON,
    contradictions JSON,
    open_questions JSON,
    rag_context_ids JSON,         -- which chunks were used as context
    prompt_version TEXT,
    created_at TEXT
)

-- Investment theses (versioned first-class objects)
theses (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    status TEXT DEFAULT 'active', -- 'active', 'closed', 'invalidated'
    core_claim TEXT NOT NULL,
    evidence JSON,                -- [{chunk_id, summary, supports_or_contradicts}]
    risks JSON,
    last_evaluated TEXT,
    created_at TEXT,
    updated_at TEXT
)

Ingestion

Single entry point — Claude parses PDFs and HTML client-side and passes already-extracted markdown plus provenance through ingest(). The server doesn't fetch URLs or parse binary formats.

def ingest(
    content: str,           # already-parsed markdown (Claude does the parsing)
    provenance: Provenance, # source_url, title, author, raw_path, accessed_at, metadata
    source_type: str,       # 'markdown' | 'tweet' | 'web' | 'pdf' | ...
) -> IngestResult:
    """Chunk content, attach provenance, return Document + Chunks. No I/O outside DB."""

The source_type discriminator drives per-type chunking:

source_typeRequired provenanceChunking behavior
markdownraw_path (URL not required for local notes)split on H2 headers; H1 → document title
tweetsource_url + authorone chunk per call — tweets are atomic
websource_urlrecursive ~400-token split over parsed body
pdfsource_url or raw_pathrecursive ~400-token split; caller passes page_number in metadata

Invariants: every chunk carries document_id; Provenance with neither source_url nor raw_path is rejected; accessed_at is auto-set if omitted.

Extraction Skills

PaperExtraction

claimed_contribution, method, key_findings, baselines, limitations, builds_on

FinancialExtraction

core_claim, evidence_chain, implied_positions, risks_acknowledged, risks_ignored, key_metrics

GeneralExtraction (fallback)

main_topic, key_points, entities_mentioned, author_stance

Analysis

Domain-agnostic RAG layer — one universal step regardless of source_type. Takes extraction output + top-5 similar chunks from the index. Asks Claude: what's new? what does it support or contradict? what connections aren't obvious? what questions should I ask now? Output stored with full provenance chain.

MCP Server

Eight tools exposed via stdio transport:

ingest(content, provenance, source_type)      → IngestResult
# Claude has already parsed the source and passes markdown + provenance fields.

search_personal_knowledge(query, limit=5)     → list[SearchResult]
# Hybrid: sqlite-vec cosine + FTS5 BM25, reciprocal rank fusion.
# "personal_knowledge" makes the local-DB boundary obvious.

get_document(doc_id)                          → DocumentDetail
# Full document with all chunks, extractions, analyses.

extract(doc_id)                               → Extraction
# Domain-specific extraction (paper / financial / general) by source_type.

analyze(doc_id)                               → Analysis
# RAG: top-5 similar chunks → Anthropic → connections, contradictions, open Qs.

list_theses(status="active")                  → list[ThesisSummary]

evaluate_thesis(claim_or_id)                  → ThesisEvaluation
# Accepts a stored thesis_id OR an ad-hoc claim string.
# RAG-searches personal knowledge, returns support/contradiction with provenance.
# Lets /thesis <claim> work without first persisting the thesis.

add_note(content, tags=[])                    → Document
# Ergonomic wrapper over ingest with source_type='markdown'.

Day 3 — MCP Server + Polish + Stretch

  2. cli.py — probe serve + probe stats
  3. Test MCP integration with Claude Code; configure /thesis <claim> slash command

✓ Claude Code calls Probe's MCP tools to ingest, search, and reason over your research index. /thesis wraps evaluate_thesis for one-shot reasoning.

What NOT to Build

No web UI — MCP server only; Claude Code is the UI.
No human-facing CLI for ingest/search/extract/analyze — those are MCP tools, not commands.
No server-side URL fetching or HTML/PDF parsing — Claude parses client-side.
No Postgres/Chroma/Pinecone — sqlite-vec only.
No async ingestion pipeline — synchronous is fine for personal use.
No automatic re-indexing on prompt changes — manual extract re-run via MCP.
No multi-user auth — single user, local files.
